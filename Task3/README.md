# architecture-pro-propdevelopment

##  Список требований для внешних интеграций

### Требования к безопасности
- Сетевой периметр:
  - Доступ только через защищённые каналы (TLS 1.2+), запрет незашифрованных протоколов
  - Обязательное ограничение по IP/ASN для сервер-сервер интеграций (allowlist)
- Криптография и ключи:
  - Обязательная проверка сертификатов, mTLS для критических интеграций
  - Ротация ключей не реже 30 дней
- Доступ к данным:
  - Доступ к данным по принципу минимальных привилегий
  - Шифрование ПДн и финансовых данных в базах данных(AES-256); маскирование/вычищение чувствительных полей в логах
  - Доступ к данным предоставляется только по ролям (RBAC)
  - Жёсткие политики паролей/секретов, секреты в Secret Manager/KMS, JIT-доступ к админ-функциям
  - Контракты партнерских API не должны содержать персональные данные
- Аутентификация и авторизация:
  - Использовать OAuth 2.0 протокол
- Наблюдаемость и реакция:
  - Полное журналирование (аутентификация, авторизация, бизнес-операции); экспорт в SIEM
  - Процедуры реагирования на инциденты и уведомления партнёров (SLA на уведомление)
- Соответствие требованиям законодательства:
  - Соответствие 152‑ФЗ (ПДн)

### Протоколы аутентификации и авторизации
  - OAuth 2.0  
  - mTLS + JWT для сервер-сервер взаимодействий

### Организация взаимодействия между системами предприятия и внешней платформой
- Все интеграции должны проходить предварительную оценку ИБ и архитектурный ревью с фиксацией рисков и компенсирующих контролей
- Использование REST API
- Вызовы внешней платформы по HTTPS
- Предусметрены вызовы хелсчеков внешней системы; в случае недоступности - ретраи и активация функционала шлагбаума / домофона через приложение
- Вызов внешней системы только для пользователей с ролью "Собственник"
